# lib — shared extension helpers

Small modules imported by two or more extensions. Pi loads each extension with
an **isolated module cache**, so these are *value-only* libraries: pure
functions, constants, and classes. Never keep cross-extension state here — a
module-level variable would have one copy per extension, not one shared copy.
`test/boundaries.test.ts` fails a module-scope `let`, `var`, `Map`, `WeakMap`, or
empty array, so this is a test and not a convention. The single exception is the
event-bus pattern in `rails.ts`, where the state lives in the caller's closure,
not in this module.

This directory sits outside `extensions/` on purpose: nothing here is a
loadable extension entrypoint, and every module is a contract shared *between*
extensions rather than private to one. A helper used by only one extension
belongs in that extension instead — see `extensions/web-access/http.ts` and
`extensions/plan/path-guard.ts`.

| Module | Responsibility |
|---|---|
| [`browser.ts`](./browser.ts) | Opening a page in the default browser, and saying what happened: the pure `browserCommand(url, platform, env)` (`$BROWSER` first, then `open` / `xdg-open` / `explorer`, or `wslview` under WSL), `openPageInBrowser(url, { autoOpen, remote, launch?, onFailure })` answering `opened` / `skipped-remote` / `skipped-off` and reporting a launcher that cannot start or exits non-zero through `onFailure` — an async `'error'` and a non-zero exit never reach a `try`, which is why the old swallow lost them — and `urlLauncher(sink)`, the one adapter a suite's effect seam needs, beside `launchDetached`, the one detached launch an OS handler uses. Shared by `file-browse`, `board`, `plan`, and `file-open`. |
| [`bus-request.ts`](./bus-request.ts) | The request/response handshake over `pi.events` for a question one extension asks another: `BusAnswer` (a value, or the promise of one an owner is still producing), `BusRequest` (the channel, the payload built around the helper's one-shot `respond`, the `unclaimed` sentence for a session where nothing listens, an optional `failed`, and an optional `timedOut` for a claim that never answers, defaulting to `unclaimed`), and `requestOverBus`, which settles exactly once — on the claimant's answer, on the microtask fallback when nobody claims, on `failed` when a claim's promise rejects, or on `timedOut` when `ANSWER_BOUND_MS` passes with the claim still open — beside `answerOn(pi, channel, answer, accepts?)`, the listener half: it refuses a payload with no `respond`, answers once with a value or the promise the work is, answers a synchronous throw as the caller's own `failed` sentence, and returns the host's unsubscribe, because a listener rebuilt per session has to drop the one it replaces. Its bound's timer is one local helper rather than `timer.ts`'s `defaultTimer`, because `session-tool.ts` imports this module and a value import of the seam would put `timer.ts` in every entry's registration graph, which may only fall; it is never `unref`'d, since a bound that exists to answer must not be the thing the loop can drop, and it is cancelled the moment the request settles. Shared by [`mode-entry.ts`](./mode-entry.ts) (enter plan mode), [`http/mount.ts`](./http/mount.ts) (a page's prefix), and [`session-tool.ts`](./session-tool.ts) (join the team, send a sign's message from a command, and claim or release paths from a turn start), so one guarantee has one body. |
| [`config.ts`](./config.ts) | The shared `bytefly.json` document and the loader over it, two ways: `loadConfigFile` for a whole file, and the shared document (`SHARED_CONFIG_FILE`) via `configSection` / `configValueAt` / `loadConfigSection` (global, then project), plus the atomic `writeConfigFile` / `writeConfigSection` / `writeConfigValue` / `writeConfigValueAt` / `writeConfigValuesAt` / `unsetConfigValueAt` (the leaf writers preserve siblings and metadata, `writeConfigValuesAt` applies several leaves in one document pass, and the last removes one and prunes what it emptied). The JSON boundary underneath — parsing, narrowing, and the atomic write — is [`json.ts`](./json.ts), so a caller that only clamps a number loads none of this. |
| [`json.ts`](./json.ts) | The untrusted-JSON boundary: the narrowing pair `clampInteger` / `clampNumber` (a number, or a string that says one; `null`, `""`, `true`, and arrays mean "unset") beside `cleanString` / `optionalString` / `asBoolean` / `stringList` / `asRecord` / `asNumber`, and the file pair on the same boundary — `readJson` (lenient: a missing, malformed, or non-object file reads as nothing), its reporting twin `readJsonResult`, and `writeJsonFile(path, value, { mode })`, the one atomic write: `tempPathFor(path)`, the one spelling of a temp name (pid plus fresh randomness, so two processes and two writes in one can never share it), and `writeTextAtomic(path, text, { mode })`, which renames that sibling over the target, sets the mode on the temp, and removes it when the write or the rename fails — with `writeJsonFile(path, value, { mode })` as its JSON face, refusing a value with no JSON form. Text and JSON land through the one body: `memory`'s note store is the text caller, and `wechat`'s `state.json` and `credentials.json` and `worktree`'s registry write through the JSON one — and `memberOf(values, value)`, the narrowest member of the same boundary: a value narrowed against the table it must be in, which is the table a tool's parameter schema is built from, so a new action reaches both or neither. Nothing here knows what a document means, which is [`config.ts`](./config.ts). |
| [`env.ts`](./env.ts) | Env-var contracts shared across extensions: the worktree environment (`ENV_ROOT`, `worktreeRoot`, `resolveEffectiveCwd`, and `effectiveRealCwd` — the effective root with symlinks resolved, which the two pages canonicalize before a containment check) used by worktree, file-browse, code-review, job, and rewind, plus `extensionEnablement` for the package-wide disable list (`ENV_DISABLED_EXTENSIONS`). |
| [`escape.ts`](./escape.ts) | `escapeHtml`: the single HTML text/attribute escape used by the browse page renderers and the Markdown and syntax highlighters, plus `decodeCodePoint`, the other half of the same boundary — one numeric character reference as text, with a surrogate or out-of-range value decoded to U+FFFD. |
| [`events.ts`](./events.ts) | Inter-extension `pi.events` channels and payloads: `JOB_FINISHED_CHANNEL` / `JobFinishedEvent` (published by `job`, consumed by bytefly's notify capability), `SUBAGENT_FINISHED_CHANNEL` / `SubagentFinishedEvent` (published by `subagent`, consumed by bytefly's footer roll-up), `WORKTREE_CHANGED_CHANNEL` / `WorktreeChangedEvent` (published by `worktree` on enter and exit, consumed by `file-browse` so an open page re-roots instead of serving the checkout the session left), and `WEB_SEARCH_PROVIDER_CHANNEL` / `WebSearchProviderEvent` (published by `web-access` at session start, consumed by bytefly's doctor so it can report the resolved provider without importing the extension — the key itself is never in the payload). |

| [`report.ts`](./report.ts) | The pending-report channel: `createPendingReporter` with `wake` / `pending` / `markReported` / `buildNotice` / `wakeRequested` / `source` / `onWoke`, returning the handlers that report at the next turn, raise at most one triggered turn per wake window, retry a wake the running turn suppressed once `agent_settled` reports an unaborted settle, and prune only their own notices; and `registerPendingChannel`, which binds those handlers to `session_start` / `session_tree` / `agent_start` / `agent_settled` / `before_agent_start` / `context` / `session_shutdown` around a `load` / `setStatus?` / `shutdown` runtime, so the order a session starts and shuts down is written once. | [`errors.ts`](./errors.ts) | `messageOf`: the one boundary that turns an unknown thrown value into a user-facing line (an `Error` yields its message, anything else is stringified), `hasErrorCode` for the branch a caller takes on one errno code (`EEXIST` means another writer won), and `attempt(promise)` — a value or the sentence its rejection is, so a door that must not throw answers with a line rather than a stack. |
| [`format.ts`](./format.ts) | Pure text/number formatting shared by renderers: `formatTokens`, `formatCount`, `formatDuration` (`450ms`, `3.2s`, `1m05s`, `2h03m`), `formatSize` (`68 B`, `12.4 kB`, `1.5 MB`), `plural` (a counted noun: `1 card`, `3 cards`, written as concatenation, crossing as `PLURAL_JS` the way `formatAge` crosses as `FORMAT_AGE_JS`, so a page and the transcript that quotes it count one way), `boundedTail` (the end of a joined tail with a `truncated` flag), `clipText` (a body bounded to a character limit with the ellipsis counted inside it — where `tui/columns.ts`'s `clip` measures terminal columns), `stripControlChars`, `sanitize`, `sanitizeLine` — the boundary for untrusted, single-line text — `lineOf` (a value read as one sanitized line), `sanitizeUntrustedLine` / `sanitizeUntrustedText` with `MAX_OUTPUT_LINE` for **program output** (OSC/CSI escapes removed whole, `\r` progress resolved, clipped), `ageWords` — the words an age is printed in (`just now`, `3m ago`) read off `formatAge`'s string, crossing as `AGE_WORDS_JS` the way `formatAge` crosses as `FORMAT_AGE_JS` — the path refusals `tooManyPaths`, `EMPTY_PATH` and `outsideRepository`, which word the sentences both normalizers print while each caller keeps its own cap and spelling, beside `overLimit`'s too-long sentence, `pathRef` — one spelling for a reference to lines, `12` or `12-30` and ` (old)`/` (new)` when a caller names the side, crossing as `PATH_REF_JS` so the review page's bar, its dialog and a thread label read the body the notice and the tool print, because a review that named its span three ways would be three chances to disagree — `shortenPath`, and `pageSource` — a function's source as a page's bundle receives it, with the host transpiler's module-namespace call sites written back to the member they name, so a spliced body may call a helper whatever module declares it (a default import is refused, since the name it stood for is gone). |
| [`timer.ts`](./timer.ts) | The three timer seams and their production defaults, each cancellable and each built so a pending timer never holds the process open: `ArmTimer` / `defaultTimer` (one shot), `RepeatTimer` / `defaultInterval` (repeating), and `abortableSleep` (resolve after a delay, reject `Error("aborted")` when a signal wins). | [`lines.ts`](./lines.ts) | `LineSplitter`, the byte-safe splitter for a stream of program output: buffers bytes and decodes only at a newline, so a UTF-8 character split across two reads survives, and caps an over-long line instead of dropping it. Shared by `job`, `watch`, and `subagent`. |
| [`pool.ts`](./pool.ts) | `mapConcurrent`: one async read per entry with at most `limit` calls in flight and results in input order, so a directory listing or a status sweep fans out without an unbounded burst or a per-entry round trip. Shared by `file-browse` and `worktree`. |

## Conventions

- **No dependencies on an extension.** Shared code imports only `node:*`, host
  packages, and other `lib/` modules; extensions import from `lib/`.
- **Inject the host seam.** Modules that need a host capability take a function
  (`RunGit`, `HttpRunner`) rather than the whole `ExtensionAPI`, so the logic is
  testable without a runtime.
- **Constants that must agree across both sides live in `tui/glyphs.ts`** — a
  glyph and the `setStatus` key are one contract, not two literals. Tool names
  shared by an orchestrating tool and the tool it calls — and parameter names
  one extension probes on another — live in `tool-names.ts`.
- **A helper that exists here must be imported, not redefined.**
  `test/shared-helpers.test.ts` fails a top-level extension declaration whose
  name is also exported by `lib/`, and a body copied from `lib/` or from any
  other file — a second extension, a sibling module, or `lib/` itself. A
  deliberate wrapper goes on that test's reasoned exception list; a copy belongs
  here with its declared capability suite.
- **An export is a promise to another module.** A value only its own file reads stays
  private, and when its last importer moves away the `export` goes with it: its row in
  the table above names what another module can reach, not what the file happens to
  declare. No test reads whether an export has an importer, so a review does.
- **A color is a role, not a token.** The rule is
  [`design-system.md`](../docs/design-system.md#color-is-a-role) and the primitives are in
  [`tui/README.md`](./tui/README.md#color-roles): draw through
  [`tui/tokens.ts`](./tui/tokens.ts) (`paint(theme, role, text)`) so a theme swap
  re-skins every surface. `TUI_TOKENS` is the one place a Pi token is named, Pi's
  tool vocabulary (`toolTitle`, `toolOutput`) included — a renderer names the
  role, and a theme that maps the token elsewhere is respected.
